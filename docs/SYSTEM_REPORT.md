# Архитектура приложения

## Сервер

Запрос проходит через Laravel web middleware: cookie-сессию, CSRF и авторизацию. Все списки требуют входа. Изменения, импорт и управление пользователями требуют актуальной роли администратора из БД. HTTP-контроллер вызывает FormRequest и сервис; SQL не формируется из пользовательских имён таблиц или колонок.

ResourceController содержит только общую пагинацию, чтение и удаление. TeacherController, ClassroomController и SoftwareController выполняют короткие операции Eloquent. ScheduleService сохраняет занятие и аудитории в транзакции, UserService защищает последнего администратора. При удалении записи не выполняется предварительный SELECT: результат DELETE показывает, существовала ли строка.

EducationQuery описывает разрешённые фильтры и сортировку. ScheduleData формирует стабильный плоский ответ, не отдавая структуру ORM клиенту. Общая оболочка JSON: `success`, `data`, `message`; ошибки содержат `success=false`, `error` и, при валидации, `errors`.

## Работа с базой

Сохраняются таблицы `users`, `teachers`, `classrooms`, `software`, `schedule` и `schedule_classrooms`. Названия существующих прикладных полей не изменены. Длинные описания дисциплины и экзаменатора помещаются в TEXT.

- `Teacher` связан с занятиями через teacher_id.
- `ScheduleEntry` имеет основную аудиторию и множество дополнительных аудиторий.
- Удаление преподавателя освобождает teacher_id; удаление аудитории сохраняет исходную семантику внешних ключей старой схемы.
- `schedule_classrooms` защищена уникальностью пары идентификаторов.
- Составные индексы покрывают дату/пару, аудиторию/дату/занятость, группу/дату и обратный поиск аудитории в связях.

Главная получает счётчики одним SQL с подзапросами COUNT вместо четырёх запросов списков. Это всё ещё четыре подсчёта на стороне БД; ускорение достигается исключением ненужных выборок и сетевых обращений, а не исчезновением стоимости COUNT.

Связи списка расписания загружаются пакетами Eloquent. В зависимости от наличия связей запрос списка содержит COUNT, выборку страницы и до трёх запросов связей. Это фиксированное число, а не запрос для каждой строки. Поиск свободных аудиторий использует NOT EXISTS по основной и дополнительным связям, отменённые занятия исключены.

## Excel

TeacherParser и ClassroomParser сохраняют правила исходных форм учебного отдела. SoftwareParser читает транспонированный лист ПО. ScheduleParser читает табличные сессии, WeeklyScheduleParser читает недельные сетки. Парсеры возвращают массивы и не обращаются к БД. ExcelValue отвечает за значения, даты и время; строка `008` не превращается в `8` при экспорте.

ImportWriter в транзакции заранее получает справочники и сохраняет строки пакетами до 200 записей. Связи аудиторий также обновляются пакетами. Преподаватели по инициалам сопоставляются в памяти; неоднозначное совпадение не назначает случайного человека. При явном разрешении новые преподаватели создаются отдельно и добавляются в локальный справочник. Это исключение может увеличивать число запросов по числу **новых** преподавателей.

Повторный импорт одного набора строк не добавляет дубликаты. Для ПО файл является снимком только указанных в нём аудиторий. Для замены расписания нужны дата и группа у каждой строки; удаление ограничивается группами из файла и диапазоном его дат. Ошибка откатывает весь импорт, включая новые аудитории.

Экспорт разделён на выборку данных и Workbook-классы оформления. Файлы хранятся вне public, доступны только создавшему пользователю и удаляются отдельной командой обслуживания. Строки Excel записываются как текст, чтобы пользовательское значение, начинающееся с `=`, не стало формулой.

## Клиент

App.vue отвечает за оболочку, выбранный раздел и тему. LoginForm, RecordForm, ListPagination и FreeClassrooms имеют отдельные шаблоны. Страницы находятся в views. Данные справочников, сессии и главной находятся в Vuex; незавершённый ввод формы хранится локально, поэтому отмена редактирования не меняет строку таблицы.

services/http.js добавляет CSRF и обрабатывает ошибки; services/education.js содержит методы предметного API. config/resources.js задаёт названия полей, колонок и фильтров. utils/format.js не имеет состояния и возвращает только текст. Vue экранирует содержимое ячеек; v-html для значений из БД не используется.

При изменении фильтра применяется задержка 300 мс. Номер запроса защищает хранилище от запоздалого ответа. Ошибки не подменяются пустым успешным списком. Таймер часов и обработчики событий очищаются при уничтожении компонентов.

## Как внести изменение

Новое поле: миграция, fillable модели, соответствующий FormRequest, конфигурация формы и колонок, затем импорт/экспорт при необходимости. Новый сложный сценарий размещайте в Services, а не в контроллере или Vue-компоненте. Комментарии описывают назначение состояния, ограничения исходного формата и причины решений; имена локальных переменных используют предметные названия.
