# Развёртывание и перенос базы

## Новая установка

Используйте команды из README. Docker запускает PHP 8.4 + Apache и MySQL 8.4. Контейнер публикует только `public/`, зависимости PHP и готовая Vue-сборка входят в образ. Миграции и первичное создание администратора выполняются при запуске приложения. База должна пройти healthcheck до старта PHP.

Для обычного сервера выполните `composer install --no-dev --optimize-autoloader`, `npm ci`, `npm run build`, настройте `.env`, `php artisan key:generate`, `php artisan migrate --force`, `php artisan hspm:admin admin --create`. Дайте веб-пользователю право записи в `storage/` и `bootstrap/cache/`. DocumentRoot задайте на каталог `public/`.

Включите HTTPS на внешнем веб-сервере и установите `APP_URL=https://ваш-домен` и `SESSION_SECURE_COOKIE=true`. В production оставьте `APP_DEBUG=false`.

## Существующая база старого приложения

1. Остановите изменения в старой системе и создайте SQL-дамп. Проверьте восстановление в отдельную базу. Сохраните прежние исходники и конфигурацию для отката.
2. Создайте отдельную БД для новой версии. Если меняется MySQL 5.7 на 8.4, выполните логический перенос дампом. Не используйте один каталог данных для разных версий MySQL.
3. Восстановите дамп, укажите новое соединение в `.env`. **Не выполняйте `migrate:fresh`**: эта команда удаляет таблицы.
4. Выполните:

```bash
php artisan hspm:adopt-legacy --backup-confirmed
php artisan migrate --force
```

Первая команда проверяет наличие всех ожидаемых таблиц и колонок и регистрирует начальную миграцию как уже выполненную. Она не удаляет и не перезаписывает прикладные данные. Несовпадение схемы останавливает перенос. Проверка имён колонок не заменяет проверку старых индексов, кодировки и целостности данных после восстановления.

Следующие миграции расширяют текстовые поля расписания и добавляют составные индексы. Пароли пользователей сохраняются: Laravel проверяет прежние bcrypt-хеши. Сессии старой версии не переносятся, нужно войти заново.

Для Docker сначала поднимите только БД, восстановите туда дамп, затем используйте `docker compose run --rm app php artisan hspm:adopt-legacy --backup-confirmed` и `docker compose run --rm app php artisan migrate --force`. После этого запускайте веб-контейнер.

Сверьте количество преподавателей, аудиторий, ПО, занятий и связей. Проверьте выборку расписания нескольких групп, права обычного пользователя, импорт и экспорт на копии. Переключайте рабочий адрес после приёмки. При откате возвращайте старую версию и сохранённую базу; не применяйте `migrate:rollback` к принятой исходной схеме.

Старые записи расписания могут иметь ключи, рассчитанные предыдущими неодинаковыми алгоритмами ручного ввода и импорта. Автоматически удалять или объединять их при переносе нельзя. Проверьте дубликаты на копии перед повторным массовым импортом исторических данных.

## Резервные копии

```bash
docker compose exec -T db sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction "$MYSQL_DATABASE"' > backup.sql
```

На старом Windows PowerShell перенаправление вывода может менять кодировку; создавайте дамп внутри Linux-контейнера через `mysqldump --result-file=/tmp/backup.sql` и копируйте его `docker compose cp db:/tmp/backup.sql ./backup.sql`.

Копируйте также `.env` в закрытое резервное хранилище. Экспорты временные; отдельно хранить их не обязательно. Проверяйте резервные копии восстановлением на отдельной БД. Не выполняйте `docker compose down -v` для обновления: флаг `-v` удаляет постоянные тома.

## Обновление

Сделайте резервную копию, сохраните `.env` и `APP_KEY`, получите проверенный код, выполните `docker compose build` и `docker compose up -d`, проверьте логи. `deploy.sh` выполняет сборку и запуск из локальных исходников; старую установку через скачивание скрипта с main не используйте для этой ветки.

Смена пароля администратора:

```bash
docker compose exec app php artisan hspm:admin admin
```

Перед интерактивной сменой удалите `ADMIN_PASSWORD` из окружения контейнера и пересоздайте его; иначе команда использует значение окружения.

Для удаления экспортов старше суток запускайте `php artisan hspm:exports-clean` либо настройте стандартный Laravel scheduler: `php artisan schedule:run` раз в минуту. Scheduler не запускается отдельным сервисом в прилагаемом Compose.
