# Учебный отдел ВШПМ СПбГУПТД

Веб-приложение для сбора и поиска данных учебного отдела — автоматизация работы с преподавателями, аудиториями, расписанием и ПО.

## Документация

- **[Инструкция пользователя и администратора](docs/USER_GUIDE.md)** — работа с интерфейсом, права ролей, импорт/экспорт, резервное копирование.
- **[Системный отчёт](docs/SYSTEM_REPORT.md)** — архитектура, API, структура БД, форматы импорта.

## Установка на сервер одной командой

Запускается из готового Docker-образа, который собирается автоматически на GitHub
(Actions публикует образ в `ghcr.io/amper24/hspm-app`).

### Быстрая установка (всё по умолчанию)

```bash
curl -fsSL https://raw.githubusercontent.com/amper24/HSPM-App/main/deploy.sh | bash
```

После запуска приложение доступно на `http://<server>:8080` (admin / admin123).

### Установка с настройками

Скрипт принимает параметры для паролей и порта:

```bash
curl -fsSL https://raw.githubusercontent.com/amper24/HSPM-App/main/deploy.sh | bash -s -- \
  --port 9090 \
  --admin-pass 'мой-секретный-пароль' \
  --db-pass 'пароль-бд' \
  --db-name hspm_edu
```

Доступные параметры:

| Флаг | Назначение | По умолчанию |
|------|-----------|--------------|
| `--port` | Порт доступа к приложению | `8080` |
| `--admin-pass` | Пароль администратора `admin` | `admin123` |
| `--db-pass` | Пароль пользователя БД | `vshpm_secret` |
| `--db-user` | Пользователь БД | `vshpm` |
| `--db-name` | Имя базы данных | `vshpm_edu` |
| `--root-pass` | Пароль root MySQL | `root_secret` |

Те же настройки можно задать через переменные окружения (`APP_PORT`, `ADMIN_PASSWORD`,
`DB_PASS`, `DB_USER`, `DB_NAME`, `MYSQL_ROOT_PASSWORD`). Настройки сохраняются в файл `.env`
в рабочей директории и используются при последующих запусках.

Для обновления на новую версию достаточно повторить эту же команду — `--pull always`
скачает последний образ.

> **Примечание:** `ADMIN_PASSWORD` применяется только при первичной инициализации БД.
> Чтобы сменить пароль уже развёрнутого приложения, используйте CLI:
> `docker exec vshpm-app php /var/www/html/hspm-admin reset-password admin новый-пароль`.

### Установка из исходников (локальная разработка)

```bash
docker compose up -d
```

После запуска подождать ~15 секунд — entrypoint проверит MySQL, инициализирует БД и выполнит миграции.

## Импорт данных

### Общая информация

**Эндпоинт**: `POST /api/import`  
**Авторизация**: admin (требуется cookie сессии)  
**Параметры** (multipart/form-data):

| Параметр | Тип | Описание |
|----------|-----|----------|
| `file` | file | Файл для импорта |
| `type` | string | Тип импорта: `teachers`, `classrooms`, `schedule`, `software` |
| `replace` | string | (опционально, `1`) для `type=schedule` — заменить снимок расписания в диапазоне дат файла (удалить записи, которых больше нет) |

**Ответ (успех)**:
```json
{"success": true, "message": "Импортировано записей: 42", "data": {"imported": 42}}
```

**Ответ (ошибка)**:
```json
{"success": false, "error": "Описание ошибки"}
```

**Поддерживаемые расширения файлов**: `.xlsx`, `.xls`  
**Защита от дублей**: все операции используют `INSERT ... ON DUPLICATE KEY UPDATE` — повторный импорт обновляет существующие записи вместо создания дубликатов.

### Пример curl-запроса

```bash
# 1. Логин
curl -c cookies.txt -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 2. Импорт
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@путь/к/файлу.xlsx" \
  -F "type=teachers"
```

## Форматы импорта

### Преподаватели (`type=teachers`)

**Файл**: `Список преподавателей ВШПМ СПбГУПТД 2025-26.xlsx`

**Структура**: 2 листа

**Лист 1** — Основные данные:
- Строка 1 — заголовок таблицы (пропускается)
- Строка 2 — заголовки колонок (пропускается)
- Строка 3+ — данные
- Колонки (фиксированные):

| Колонка | Поле | Пример |
|---------|------|--------|
| A | `№` | 1 |
| B | `Ф.И.О.` | Иванов Иван Иванович |
| C | `Должность` | доцент |
| D | `Степень` | к.экон.н. |
| E | `Звание` | доцент |
| F | `Кафедра / форма занятости` | КиКТ / штат. |

- Колонка F разбирается: часть до `/` — кафедра, после — форма занятости
- Строки-разделители с названиями кафедр («Кафедра Графики» без должности) автоматически пропускаются
- Форма занятости нормализуется: `штат.` → `штатный`, `внеш. совм.` → `внешний совместитель`, `ГПХ` → `ГПХ`

**Лист 2** — Контакты:
- Строки 1-3 — заголовки (пропускаются)
- Строка 4+ — данные
- Колонки: `B` = ФИО, `C` = Почта, `D` = Телефон
- Сопоставляется с листом 1 по ФИО (нормализованный ключ: нижний регистр, единичные пробелы)
- Если контакт не найден в листе 1 — создается базовая запись с ФИО и контактами

**Уникальность**: `(last_name, first_name, middle_name)` — повторный импорт обновляет должность, степень, звание, кафедру, занятость, email и телефон.

**Пример curl**:
```bash
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@Прил_Уч_отдел - задание/Список преподавателей ВШПМ СПбГУПТД 2025-26.xlsx" \
  -F "type=teachers"
```

### Аудитории (`type=classrooms`)

Поддерживает **два формата**, выбор происходит автоматически.

#### Формат 1 — «Тех хар-ка» (из файла `Тех_хар_ка_ПО_ауд.xlsx`)

Активируется, если в книге есть лист с названием «Тех хар-ка».

**Структура листа «Тех хар-ка»**:
- Строка 1 — заголовок (пропускается)
- Строка 2 — пустая
- Строка 3 — заголовки колонок (пропускается)
- Строка 4+ — данные

**Фиксированные колонки**:

| Колонка | Поле | Тип | Пример |
|---------|------|-----|--------|
| A | `№ ауд` | string | 201 |
| B | `Здание` | В/Д/БМ | В |
| C | `Тип` | string | лекционная аудитория |
| D | `Количество ПК` | int | 1 |
| E | `Проектор` | 1/пусто | 1 |
| F | `Колонки` | 1/пусто | |
| G | `Количество посадочных мест` | int | 24 |

**Пример curl**:
```bash
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@Прил_Уч_отдел - задание/Тех_хар_ка_ПО_ауд.xlsx" \
  -F "type=classrooms"
```

#### Формат 2 — Универсальный

Активируется, если лист «Тех хар-ка» не найден.

**Структура**:
- Строка 1 — заголовки колонок с ключевыми словами
- Строка 2+ — данные

**Ключевые слова для авто-определения колонок** (регистр не важен):

| Поле | Распознаваемые заголовки |
|------|--------------------------|
| `room_number` | `№ ауд`, `№ аудитории`, `room`, `аудитория` |
| `building` | `корпус`, `building`, `здание` |
| `room_type` | `тип`, `type` |
| `computers_count` | `пк`, `компьютер`, `computers` |
| `has_projector` | `проектор`, `projector` |
| `has_speakers` | `колонк`, `speakers` |
| `seats` | `мест`, `seats`, `посад` |

Если заголовки не найдены, система пытается угадать:
- Колонка с 2-4-значными числами → `room_number`
- Колонка с `В`/`Д`/`БМ` → `building`

**Пример своего файла** (`rooms.xlsx`):

| № аудитории | Корпус | Тип | Компьютеров | Проектор | Колонки | Мест |
|------------|--------|-----|-------------|----------|---------|------|
| 101 | Д | лекционная | 1 | 1 | 0 | 50 |
| 102 | В | лаборатория | 15 | 0 | 1 | 20 |

**Значения для флагов** (`has_projector`, `has_speakers`):
- `1`, `да`, `есть` → `1`
- всё остальное → `0`

**Пример curl**:
```bash
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@rooms.xlsx" \
  -F "type=classrooms"
```

### Программное обеспечение (`type=software`)

**Файл**: `Тех_хар_ка_ПО_ауд.xlsx`

**Структура**: лист «ПО»
- Строка 1 — заголовок таблицы (пропускается)
- Строка 2 — пустая
- Строка 3 — номера аудиторий: `331 аудитория`, `444 ауд`, `202 ВЗН ауд` и т.д.
- Строка 4+ — названия ПО (одна программа на ячейку)

**Правила парсинга заголовков колонок**:
- Из строки заголовка извлекаются первые цифры → номер аудитории
- Если в заголовке есть «ВЗН» → корпус `В`, иначе `Д`
- Каждая упомянутая в заголовках аудитория автоматически создается в таблице `classrooms` (INSERT IGNORE — не дублирует существующие)

**Пример curl**:
```bash
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@Прил_Уч_отдел - задание/Тех_хар_ка_ПО_ауд.xlsx" \
  -F "type=software"
```

### Расписание (`type=schedule`)

Поддерживает **четыре формата**. Сначала всегда пробуется универсальный формат с авто-определением по заголовкам. Если он не сработал — используется один из трех фиксированных форматов.

#### Формат 1 — Универсальный (по заголовкам) ⭐ Новое

Активируется **всегда первым**. Ищет строку заголовков с ключевыми словами в первых 5 строках файла.

**Ключевые слова для авто-определения колонок** (регистр не важен):

| Заголовок | Поле | Пример значения |
|-----------|------|-----------------|
| `Дата`, `date` | `date` | `22.12.2025` |
| `Время`, `time` | `time` | `11:40` |
| `Группа`, `group`, `шифр` | `group_code` | `1-ГИД-19` |
| `Дисциплина`, `discipline` | `discipline` | `Информационные технологии` |
| `Вид`, `тип`, `экз` | `exam_type` | `конс.` |
| `Экзаменатор`, `преподаватель`, `examiner` | `examiner` | `Воронова О.Е.` |
| `Аудитория`, `room`, `classroom`, `каб` | `classroom` | `ДО` |
| `Перенос`, `transfer`, `отмена` | `transfer_cancel` | `перенос` |
| `Кафедра группы`, `group dep` | `group_department` | `КиКТ` |
| `Кафедра преп.`, `teacher dep` | `teacher_department` | `ИиУС` |
| `Должность преп.`, `teacher pos` | `teacher_position` | `ст. пр.` |
| `Сроки сессии (начало)`, `сессия с` | `session_start` | `22.12.2025` |
| `Сроки сессии (окончание)`, `сессия по` | `session_end` | `30.12.2025` |

**Минимальный набор**: достаточно 3 любых ключевых поля — остальные будут `NULL`.

**Особенности**:
- Если в ячейке несколько дат (например `22.12.2025 12.01.2026`), берется первая
- Аудитория ищется в таблице `classrooms` для связи `classroom_id`
- Экзаменатор ищется в `teachers` для связи `teacher_id`
- Тип экзамена нормализуется: `конс.` → `консультация`, `экз.` → `экзамен`
- Проверка дубликатов: если запись с такими же date + time_start + discipline + examiner + group_code уже существует — пропускается

**Пример структуры**:

| № | Дата | Время | Группа | Дисциплина | Вид | Экзаменатор | Аудитория | Перенос |
|----|------|-------|--------|------------|-----|-------------|-----------|---------|
| 1 | 2025-01-15 | 15:20-16:20 | 1-ГИД-19 | Информационные технологии | конс. | Воронова О.Е. | ДО | |

**Пример curl**:
```bash
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@расписание.xlsx" \
  -F "type=schedule"
```

#### Формат 4 — RichText (`.xlsx`)

Файлы: `Расписание студентов очной формы ИМТ... .xlsx` и др. (широкие таблицы)

**Признак**: в первых 10 строках **более 3** RichText-ячеек.

**Структура**:
- Строки 1-6 — заголовки (пропускаются)
- Строка 7+ — данные

**Колонки**:
- `A` — день недели (пропускается)
- `B` — время (строка `HH:MM-HH:MM` или RichText)
- `C` и далее (до 20-й) — дисциплины в RichText-формате + номера аудиторий

**Алгоритм**:
- По `B` парсится время
- По колонкам 3+ собирается весь текст: RichText → `getPlainText()`
- В тексте ищутся: аудитории (`В237`, `Д331`), преподаватели (`Фамилия И.О.`), тип занятия (`лекц.`, `прак.`, `лаб.`)

## Порядок импорта

Для корректной работы связей (`schedule.teacher_id`, `schedule.classroom_id`) соблюдайте порядок:

1. **Преподаватели** (`type=teachers`)
2. **Аудитории** (`type=classrooms`)
3. **ПО** (`type=software`) — дополнит аудитории
4. **Расписание** (`type=schedule`) — свяжется с преподавателями и аудиториями

```bash
# Полный цикл импорта из папки задания:
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@Прил_Уч_отдел - задание/Список преподавателей ВШПМ СПбГУПТД 2025-26.xlsx" \
  -F "type=teachers"

curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@Прил_Уч_отдел - задание/Тех_хар_ка_ПО_ауд.xlsx" \
  -F "type=classrooms"

curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@Прил_Уч_отдел - задание/Тех_хар_ка_ПО_ауд.xlsx" \
  -F "type=software"

# Для каждого файла расписания:
curl -b cookies.txt -X POST http://localhost:8080/api/import \
  -F "file=@Прил_Уч_отдел - задание/Расписание/1 семестр/sess_imt_och.xlsx.xls" \
  -F "type=schedule"
```

|---------|-----------|----------------|

| `classrooms` | Аудитории | `(room_number, building)` |
| `teachers` | Преподаватели | `(last_name, first_name, middle_name)` |
| `schedule` | Расписание | `(classroom_id, date, pair_number, time_start)` |
| `software` | ПО | `(room_number, building, name)` |

## CLI-утилита администрирования (`hspm-admin`)

В контейнере доступна консольная утилита для управления приложением без веб-интерфейса.

### Использование

```bash
docker exec vshpm-app php /var/www/html/hspm-admin [команда] [опции]
```

### Команды

| Команда | Описание | Пример |
|---------|----------|--------|
| `info` | Общая информация о системе (PHP, MySQL, БД, URL, статистика) | `hspm-admin info` |
| `stats` | Статистика БД (количество записей, связи, размер) | `hspm-admin stats` |
| `db-check` | Проверка подключения к БД, таблиц и индексов | `hspm-admin db-check` |
| `reset-password` | Сброс пароля пользователя (по умолчанию admin, пароль генерируется) | `hspm-admin reset-password` |
| `reset-password USER PASS` | Сброс с указанным паролем | `hspm-admin reset-password admin newpass` |
| `create-user LOGIN PASS [role] [name]` | Создать пользователя (role: admin/user) | `hspm-admin create-user ivanov pass123 admin "Иванов И.И."` |
| `list-users` | Список всех пользователей | `hspm-admin list-users` |
| `truncate TABLE` | Очистить таблицу (teachers/classrooms/schedule/software) | `hspm-admin truncate teachers` |
| `import TYPE FILE` | Импорт файла (без веб-интерфейса) | `hspm-admin import teachers /path/to/file.xlsx` |
| `backup` | Создать бекап БД в `/var/www/html/backups/` | `hspm-admin backup` |
| `restore [file]` | Восстановить БД из бекапа (без аргументов — список доступных) | `hspm-admin restore` |
| `help` | Справка по всем командам | `hspm-admin help` |

### Примеры

```bash
# Информация о системе
docker exec vshpm-app php /var/www/html/hspm-admin info

# Статистика
docker exec vshpm-app php /var/www/html/hspm-admin stats

# Сброс пароля (автогенерация)
docker exec vshpm-app php /var/www/html/hspm-admin reset-password

# Сброс пароля с указанием
docker exec vshpm-app php /var/www/html/hspm-admin reset-password admin mynewpassword

# Создать пользователя-админа
docker exec vshpm-app php /var/www/html/hspm-admin create-user director pass456 admin "Петров П.П."

# Импорт через CLI
docker cp файл.xlsx vshpm-app:/tmp/
docker exec vshpm-app php /var/www/html/hspm-admin import teachers /tmp/файл.xlsx

# Очистить расписание
docker exec vshpm-app php /var/www/html/hspm-admin truncate schedule
```

### Бекап и восстановление

Бекапы сохраняются в Docker-том `backups` (монтируется в `/var/www/html/backups`).
Том сохраняется между перезапусками контейнера.

```bash
# Создать бекап
docker exec vshpm-app php /var/www/html/hspm-admin backup

# Посмотреть доступные бекапы
docker exec vshpm-app php /var/www/html/hspm-admin restore

# Восстановить из конкретного бекапа
docker exec vshpm-app php /var/www/html/hspm-admin restore /var/www/html/backups/dump_2026-08-11_18-36-17.sql
```

## Автоматические миграции БД

При каждом запуске контейнера `docker-entrypoint.sh` проверяет наличие необходимых колонок и индексов и добавляет их автоматически. Это позволяет обновлять приложение без ручного изменения схемы БД:

- **Колонки `schedule`**: `discipline`, `group_department`, `group_code`, `teacher_department`, `teacher_position`, `examiner`, `exam_type`, `session_start`, `session_end`
- **Уникальные ключи**: `schedule.idx_unique_schedule`, `software.idx_unique_software`
