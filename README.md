# Учебный отдел ВШПМ

Приложение для преподавателей, аудиторий, программного обеспечения и расписания. Серверная часть перенесена на Laravel 13, интерфейс разделён на Vue 2.7 компоненты, Vuex-хранилища и сервисы запросов. Исходные функции больше не вызываются через самописный PHP-роутер.

## Что потребуется

- PHP 8.4 с PDO MySQL/SQLite, mbstring, intl, GD, ZIP, XML и OpenSSL; Composer 2.
- Node.js 22 и npm для сборки фронтенда.
- Для нового сервера: MySQL 8.4 и Docker Compose v2 либо собственный PHP/Apache/Nginx.

В старом ТЗ указаны PHP 7.2 и Ubuntu 16.04. Эта версия на PHP 7.2 **не запускается**. Серверную среду нужно обновить. Vue 2.7 сохранён по исходному ТЗ; переход на Vue 3 в этот рефакторинг не включён.

## Запуск в Docker

Команды выполняются из каталога проекта. Сначала скопируйте `.env.example` в `.env` и задайте `DB_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `ADMIN_PASSWORD` (не менее 12 символов), а также `APP_URL` и `APP_PORT`.

```bash
cp .env.example .env
# Отредактируйте .env перед следующими командами.
docker compose build
docker compose run --rm --no-deps app php artisan key:generate --show
```

Последняя команда выводит ключ `base64:...`. Сохраните его в `APP_KEY` файла `.env`. Используйте один постоянный ключ для этой установки, не заменяйте его при обновлении.

```bash
docker compose up -d
docker compose logs --tail=100 app
```

Откройте `http://localhost:8080`. Логин задаётся через `ADMIN_USERNAME` (по умолчанию `admin`), пароль берётся из `ADMIN_PASSWORD`. Общего встроенного пароля нет. При повторном запуске существующая учётная запись не перезаписывается. После первого запуска можно убрать `ADMIN_PASSWORD` из `.env`.

База и рабочие файлы сохраняются в Docker volumes. **Не подключайте старый volume MySQL 5.7 непосредственно к MySQL 8.4**: переносите данные через проверенный SQL-дамп. Порядок переноса описан в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Локальная разработка

```bash
composer install
npm ci
cp .env.example .env
php artisan key:generate
```

Для MySQL заполните параметры `DB_*`. Для отдельной локальной проверки можно выбрать `DB_CONNECTION=sqlite`, создать пустой `database/database.sqlite` и указать его **абсолютный путь** в `DB_DATABASE`.

```bash
php artisan migrate
php artisan hspm:admin admin --create
npm run build
php artisan serve
```

Команда создания администратора запросит пароль скрытым вводом. При разработке фронтенда запускайте `npm run dev` во втором терминале. Для Windows используйте `Copy-Item .env.example .env`; пустой SQLite-файл создаётся через `New-Item database/database.sqlite -ItemType File`. Если PHP на Windows некорректно обрабатывает кириллицу в пути при `artisan serve`, разместите проект в каталоге с латинским именем, например `C:\projects\HSPM-App`.

## Структура

```text
app/
  Http/Controllers/     HTTP-маршруты: принять запрос, вызвать сервис, вернуть ответ
  Http/Requests/        Правила полей и валидация форм
  Http/Middleware/      Проверка роли администратора
  Http/Resources/       Представление расписания для клиента
  Models/               Eloquent-модели и связи таблиц
  Queries/              Фильтры списков и отчёт по занятости
  Services/Import/      Парсеры Excel и пакетная запись
  Services/Export/      Формирование Excel без SQL внутри форматирования
  Services/Schedule/    Разбор аудиторий, ключ занятия, транзакционное сохранение
  Console/Commands/     Администрирование, импорт, принятие старой схемы
resources/js/
  components/           Формы, пагинация, поиск свободных аудиторий
  views/                Главная, справочники, импорт
  store/                Сессия, данные справочников и состояние главной
  services/             HTTP-клиент и методы API
  config/               Колонки, фильтры и поля форм
  utils/                Чистые функции форматирования
database/migrations/    Структура и изменения БД
routes/                 Web/API-маршруты и консольные задания
tests/                  Серверные, клиентские и проверки исходных файлов
```

Веб-сервер должен публиковать **только `public/`**. Старые каталоги `api/`, `js/` и корневой `index.html` удалены, чтобы не оставлять второй способ выполнения старого кода.

## Проверки

```bash
php vendor/bin/phpunit
npm test
npm run build
php vendor/bin/pint --test
```

Отдельный прогон на тестовой MySQL-базе: заполните `DB_PASSWORD`, создайте пустую `hspm_test` и выполните `php vendor/bin/phpunit -c phpunit.mysql.xml`. **Нельзя направлять тесты в рабочую базу:** они создают и очищают таблицы.

Реальные Excel-файлы можно проверить независимо от рабочей БД:

```bash
php tests/check_source_archive.php /path/to/extracted/archive /path/to/report.json
```

Проверка использует SQLite в памяти, импортирует каждый файл дважды и сравнивает число строк. Сам архив не включён в репозиторий и поставку.

## Особенности исходных данных

Недельные сетки без календарных дат сохраняются с днём недели. Они доступны в общем разделе расписания, но автоматически не разворачиваются в даты семестра и не определяют свободные аудитории на конкретную дату. Для этого нужны подтверждённые границы семестра и правила чередования недель.

Журнал переносов с диапазонами дат и сокращёнными списками групп не считается снимком расписания. Его импорт отклоняется с понятным сообщением, чтобы не применить изменения к неверным занятиям. Переносы и отмены можно задавать в редакторе расписания.

В приложенном списке преподавателей ФИО не заполнены. Такой файл отклоняется без изменения базы; импорт преподавателей с заполненными ФИО проверен на автоматически сформированном тестовом Excel.
